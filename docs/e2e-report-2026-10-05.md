## Issues found and fixes

1. **Claude Code's prompt suggestion text in the agents' input boxes (fixed).** After each turn, Claude Code shows dim ghost text in the input box, for example `❯ Test the implementation.` in the orchestrator's pane and `❯ commit this` in coder-1's.
   - **Why it matters:**
     - It costs one extra model call per turn for every agent.
     - `dialogs.input_box_text()` reads the capture without attributes, so the ghost text looks like typed input to the supervisor.
     - Delivery still worked, because a paste replaces the suggestion and Enter is pressed only after the pointer id is visible. Even so, a nobody-typed suggestion sitting in an agent's input box is a hazard.
   - **Fix:** `launcher.settings_dict` now writes `"promptSuggestionEnabled": false` to each agent's own `--settings` file, and `agent_env` sets `CLAUDE_CODE_ENABLE_PROMPT_SUGGESTION=0`. Neither change touches user config. The test is in `tests/unit/test_launcher.py`.
   - **Verified live:** after `ads restart supervisor` and `ads restart orchestrator --resume`, the input box stayed empty after the turn.
   - **Gotcha:** a running supervisor keeps the launcher code it was started with. After changing launcher code, run `ads restart supervisor` before `ads restart <agent>`.
2. **The final plan was edited after the evaluator's pass (fixed in the prompt).** The evaluator passed v1, which had 7 minor findings. The planner then applied those findings as v2 and finalized v2 without a second review. It disclosed this honestly ("v2 itself was not sent for a second review"), but the guarantee that the plan was verified by the evaluator no longer held for the final text.
   - **Fix:** `prompts/planner.md` §4 now says the final plan must be exactly what the evaluator reviewed. Applying findings after a pass means writing v<N+1> and sending it for another review (if rounds remain); otherwise the findings are listed as open minor items. `tests/unit/test_prompts.py` asserts the new phrase. A Lab Note records the lesson.
3. **No `ads` defect in delivery, hooks or ledger rules surfaced.** Restart, adoption and resume behaved as documented:
   - `ads restart orchestrator` while idle: the queued human instruct was delivered right after SessionStart.
   - `ads restart supervisor`: all 7 agents were adopted.

## Observations and remaining risks

- **Git identity.** The machine has no git identity configured, so the developer committed with `git -c user.name=Caleb -c user.email=…`. It took the identity from the user's global context. This is reasonable, but it was the agent's own decision. Set `git config user.name/email` in projects where authorship matters.
- **Test docs are not committed.** Only the developer commits, and it does so before the test phase, so `docs/test-*.md` stays untracked. The orchestrator pointed this out. It needs a later dev instruction, or a rule change.
- **coder-2 was not used.** This is expected for a 2-step plan. The parallel coder path, with disjoint ownership and one open task per coder, was not exercised with real agents. It is covered only by the ledger unit tests (rule 1 hold) and the fake-agent smoke test.
- **Not exercised with real Claude:** hold, supersede and cancel, the question → auto-answer path, nudges, `/clear` → restarting, StopFailure/api-error, and an unknown dialog. These are covered by unit and integration tests and by `tests/e2e/smoke_fake.sh` (which covers hold and the human exemption) with fake agents only.
- **Lab Notes were not used by agents** in a clean run. Whether agents record lessons on their own after a real mistake is still unproven.
- **Turn time is dominated by the orchestrator's pane summary.** In phase 1 it took 1 min 48 s, which is fine for the human but is the longest single turn.
- **Process exit after stop.** `ads stop` returns before the `claude` processes have fully exited, which took up to about 5 s. This is harmless, but a quick `ads <project>` restart could briefly overlap with them.
